## Resolution

Miraio will keep native playback and supplemental subtitle rendering behind a strict capability boundary.

### Native playback ownership

- `AVPlayerView` owns macOS transport controls, seeking, system speeds, full screen, Picture in Picture, Now Playing publication, and recognized embedded audio and legible-track selection. A future iOS shell uses `AVPlayerViewController` for the equivalent platform behavior.
- An AVFoundation-based Playback Session coordinator owns `AVPlayer` and player-item lifecycle, current media time, seeking, rate, observable playback state, and item replacement.
- Miraio-owned presentation owns Translation, Source, Quality, external ASS choice, fallback notices, the hover surface, and the on-demand inspector. It does not rebuild native transport or media controls.
- Native media delivery remains gated on the official Anime365 contract. No custom resource loader or undocumented authorization path is introduced by this architecture.

### Narrow supplemental boundary

- Native AVKit remains responsible for every recognized embedded or HLS legible track.
- External ASS is the sole V1 supplemental path. Miraio will not build a replacement subtitle stack for native tracks, SRT, or WebVTT without a future official service requirement.
- ASS semantics remain behind a narrow engine adapter rather than being flattened into a generic cue model. The adapter accepts bounded in-memory ASS data, viewport and safe-area geometry, appearance capabilities, and the active media time; it produces a noninteractive visual overlay and may expose a separate semantic dialogue stream for accessibility.
- The active `AVPlayerItem` timebase is the only subtitle clock. Rendering reacts to cue boundaries, seeks, item changes, viewport changes, and player state; display-linked updates are allowed only while visible playback requires a supported time-varying effect. There is no independent subtitle clock or background polling.

### Trust, appearance, and accessibility

- Subtitle acquisition stays outside the renderer. The renderer receives immutable, size-bounded bytes and has no network, credential, cookie, Access Token, signed-URL, or persistence access.
- V1 does not fetch fonts or resources named by subtitle content. It uses bounded parsing and rendering plus bundled or system font fallback; malformed or excessive input produces a typed renderer failure without destabilizing native playback.
- Authored ASS composition is the default. The renderer advertises only those appearance adjustments it can apply without corrupting the selected track, and Miraio exposes controls from those capabilities rather than guessing from style names.
- Playback and subtitle controls, selection, renderer status, degradation, and PiP limitations remain keyboard- and VoiceOver-accessible. The visual overlay must not produce duplicate or continuously interrupting announcements.

### Platform reuse and release gates

- Media-time synchronization, ASS engine adaptation, renderer state, input validation, and appearance capabilities are reusable across Apple platforms. Player hosting, overlay attachment, control-safe geometry, full-screen transitions, and PiP integration remain platform-specific.
- If a native equivalent legible track exists, Miraio may use it for PiP. Otherwise, when supplemental ASS contains dialogue and cannot be carried into PiP, Miraio disables PiP for that Playback Session with an explanation; it never silently removes required dialogue.
- Dialogue, timing, positioning, authored styles, overlapping dialogue and signs, and readable static signs are release gates. Karaoke animation, drawings, and advanced animation may degrade to a readable static result.
- A focused prototype must select the real ASS engine and validate fidelity, licensing, sandbox and distribution compatibility, Apple Silicon and future iOS integration, bounded-input behavior, accessibility, full-screen and PiP behavior, stability, and the map's energy constraints. `libass` is the leading candidate, not a decision made without that evidence. If no candidate clears the core fidelity line, native V1 playback remains blocked for content dependent on external ASS; the documented hosted Anime365 handoff is only an explicit degraded path.
