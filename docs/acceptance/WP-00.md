# WP-00 Product foundation evidence

Issue #33 is exercised at the package, macOS UI, and distribution-configuration boundaries. CI retains three Xcode result bundles, the macOS package-test log, and the audit logs as the `foundation-evidence` artifact.

| Acceptance | Executable evidence |
| --- | --- |
| `FND-01` | `swift test --package-path Packages/MiraioCore`; the `MiraioCore-Package` suite on an iOS 26 Simulator; the `Miraio` macOS build and `MiraioLaunchTests` launch assertion. |
| `FND-02` | `scripts/verify-foundation.sh` audits the exact eight-product dependency graph, the single macOS application product, and the absence of UI/lifecycle observation in shared sources. Swift access control keeps adapter source types internal until their work packages introduce consumer-owned public contracts. |
| `FND-03` | `ApplicationLifecycleAuthorityTests` schedules overlapping commands through injected capabilities and proves an obsolete completion cannot replace newer actor state. |
| `FND-04` | Shared lifecycle-command policy tests and `AppCompositionTests` prove the macOS shell translates platform state into typed shared commands. |
| `FND-05` | Homebrew and Store builds plus `scripts/verify-channel-equivalence.sh` compare identity, version/build, architecture, deployment target, compile conditions, sandbox, Hardened Runtime, and entitlement inputs. |
| `PRIV-01` | `scripts/verify-foundation.sh` requires the entitlement plist to contain exactly App Sandbox and outgoing network access. Both channel configurations reference that same plist and retain ATS defaults. |
| `REL-01` | `scripts/verify-foundation.sh` checks Release Please, `version.txt`, and Xcode version agreement. CI supplies `git rev-list --count HEAD` as the deterministic build number. Release Please owns Conventional Commit versioning and changelog updates; only its scoped GitHub App pull request is eligible for required-check-gated auto-merge. |

Distribution signing, notarization, Store export, Cask publication, and exact signed-artifact qualification remain owned by WP-09 and WP-10. Their absence cannot be represented as passing evidence in WP-00.
