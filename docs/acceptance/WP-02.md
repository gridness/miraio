# WP-02 acceptance evidence

Issue [#35](https://github.com/gridness/miraio/issues/35) is exercised at the shared package, adapter, and macOS UI seams. CI retains the package transcript and macOS unit/UI result bundles in the existing acceptance artifact.

| Acceptance | Executable evidence |
| --- | --- |
| `AUTH-01` | `AuthenticationAuthorityTests.signsInAndBindsCredentialToVerifiedProfile` proves pending-token verification and immutable Profile binding. `Anime365AuthenticationClientTests.signsInThroughDocumentedExchange` proves the documented `/api/login` exchange and maps only the issued Access Token. `MiraioLaunchTests.testRejectedSignInClearsPasswordAndPreservesPublicDestinations` proves truthful rejection copy and password clearing. |
| `AUTH-02` | `AuthenticationAuthorityTests` covers signed out, credential unavailable, verifying, authenticated Profile with unknown/inactive eligibility, Subscriber, and incomplete sign-out. `MiraioLaunchTests.testCredentialUnavailableAndIncompleteSignOutRemainDistinct` and `testVerifyingProfileAndSubscriberEligibilityStatesRemainDistinct` retain accessibility-visible UI evidence while public destinations remain enabled. |
| `AUTH-03` | `AuthenticationAuthorityTests.revalidatesAtSettledForegroundTrigger`, `refreshesEligibilityExplicitly`, and `gatesProtectedOperationAfterDueVerification` prove cold-launch, explicit, foreground-age, and protected-operation triggers without polling or `premiumUntil` interpretation. |
| `AUTH-04` | `AuthenticationAuthorityTests.resolvesAmbiguousProtectedFailure` executes invalid-authentication, inactive, active, and unavailable `/api/me` disambiguation outcomes with the required token-retention policy. |
| `AUTH-05` | `AuthenticationAuthorityTests.rejectsSignInCompletionObsoletedBySignOut`, `rejectsCredentialWriteObsoletedBySignOut`, `cancelsAuthenticatedRequestsOnSignOut`, and `blocksProfileReplacementWithoutSignOut` prove generation safety across state and durable credential mutations, cancellation, and explicit Profile replacement. |
| `AUTH-06` | `AuthenticationAuthorityTests.persistsAndRetriesIncompleteSignOut` proves immediate protected clearing, successful deletion, retryable failed deletion, relaunch recovery, and protected-operation blocking. Authentication owns no Watch History deletion port, and the macOS UI keeps Watch History enabled throughout authentication failures. |
| `REC-03` | The protected-access decision tests cover sign-in required, verification required, Subscription required, and incomplete-sign-out gates while UI tests prove Catalogue and Watch History continuity. The inactive UI exposes only Refresh, public Anime365 handoff, and sign-out. |
| `PRIV-03` | `KeychainAccessTokenVaultTests` uses a temporary Keychain item to prove Profile binding and token-only value storage, verifies the production data-protection/non-synchronizing/`WhenUnlockedThisDeviceOnly` configuration, and proves relaunch-safe incomplete-sign-out metadata. Exact signed-artifact Keychain inspection remains an RC physical-Mac lane as required by the canonical matrix. |

`RedactedDiagnosticsTests.redactsAccessTokenRepresentations`, categorical adapter failures, synthetic provider fixtures, and the cookieless no-cache authenticated session ensure credentials, provider bodies, and credential-bearing URLs do not enter retained diagnostics.
